    3.5. Comentarios estructurados y documentación con Javadoc¶

    1. Introducción¶

    Los comentarios permiten explicar el propósito y el funcionamiento del código fuente. En Java, el compilador ignora los comentarios: no modifican el comportamiento del programa.

    Cuando un proyecto crece, resulta especialmente útil disponer de documentación estructurada, que pueda consultarse sin necesidad de leer toda la implementación. Java proporciona la herramienta Javadoc, incluida en el JDK, para generar documentación HTML a partir de comentarios especiales.

    Objetivos

    • Distinguir los tipos de comentarios en Java.
    • Documentar clases, atributos, constructores y métodos.
    • Utilizar las principales etiquetas de Javadoc.
    • Generar y consultar documentación HTML.
    • Configurar la generación mediante opciones de línea de comandos.

    2. Tipos de comentarios en Java¶

    2.1. Comentarios de una línea¶

    Comienzan con // y terminan al finalizar la línea.

    int edad = 18; // Edad del alumno
// Comprobamos si es mayor de edad
if (edad >= 18) {
    System.out.println("Mayor de edad");
}

    2.2. Comentarios de varias líneas¶

    Comienzan con /* y terminan con */.

    /*
 * Calculamos el importe final
 * aplicando el descuento correspondiente.
 */
double precioFinal = precio * (1 - descuento);

    2.3. Comentarios de documentación Javadoc¶

    Comienzan con /** y terminan con */. Se colocan inmediatamente antes del elemento que documentan.

    /**
 * Calcula el cuadrado de un número entero.
 *
 * @param numero número que se desea elevar al cuadrado
 * @return cuadrado del número indicado
 */
public static int cuadrado(int numero) {
    return numero * numero;
}
    Tipo Delimitadores Finalidad Genera documentación Javadoc
    Una línea // Explicaciones breves No
    Bloque /* ... */ Explicaciones extensas No
    Documentación /** ... */ Describir la API del programa Sí

    Importante

    No es necesario comentar cada instrucción. Es preferible explicar qué hace un método, qué significan sus parámetros y qué condiciones deben cumplirse, en lugar de repetir lo que ya expresa el código.

    3. ¿Qué es Javadoc?¶

    Javadoc es una herramienta del JDK que analiza el código Java y sus comentarios de documentación para generar páginas HTML navegables.

    El proceso es:

    Código fuente (.java)
        ↓
Comentarios /** ... */
        ↓
Herramienta javadoc
        ↓
Documentación HTML
        ↓
Abrir index.html en el navegador

    La documentación generada permite consultar clases, constructores, métodos, campos, parámetros, valores devueltos y referencias a otros elementos.

    3.1. Estructura de un comentario Javadoc¶

    /**
 * Primera frase: resumen breve del elemento.
 *
 * Descripción adicional con información sobre su uso.
 * Puede ocupar varias líneas.
 *
 * @etiqueta información asociada
 */
    • Resumen: primera frase descriptiva, que aparece en los listados de Javadoc.
    • Descripción: explicación adicional, opcional.
    • Etiquetas de bloque: comienzan normalmente con @ y se escriben después de la descripción.
    • Etiquetas en línea: se insertan dentro del texto usando la forma {@etiqueta ...}.

    4. Documentar los elementos de un programa¶

    4.1. Documentar una clase¶

    /**
 * Representa a un alumno matriculado en un ciclo formativo.
 * Permite almacenar su nombre y su edad.
 *
 * @author Departamento de Informática
 * @version 1.0
 * @since 1.0
 */
public class Alumno {
    // Atributos y métodos de la clase
}

    @author identifica al autor; @version indica la versión del elemento; @since señala desde qué versión está disponible.

    Visualización de autor y versión

    Para mostrar @author y @version en el HTML generado, hay que activar las opciones -author y -version del comando javadoc.

    4.2. Documentar atributos y constantes¶

    /** Nombre completo del alumno. */
private String nombre;

/** Edad del alumno expresada en años. */
private int edad;

/** Edad mínima exigida para la matrícula. */
public static final int EDAD_MINIMA = 16;

    Los atributos privados pueden documentarse, aunque no aparecerán en la salida predeterminada si no se utiliza una opción de visibilidad adecuada, como -private.

    4.3. Documentar constructores¶

    /**
 * Crea un alumno con su nombre y edad.
 *
 * @param nombre nombre completo del alumno
 * @param edad edad del alumno en años
 */
public Alumno(String nombre, int edad) {
    this.nombre = nombre;
    this.edad = edad;
}

    4.4. Documentar métodos con parámetros y retorno¶

    /**
 * Calcula el precio final después de aplicar un descuento.
 *
 * @param precio precio inicial del producto
 * @param descuento porcentaje de descuento entre 0 y 100
 * @return precio final con el descuento aplicado
 */
public static double calcularPrecio(double precio, double descuento) {
    return precio * (1 - descuento / 100);
}

    Cada parámetro debe tener su propia etiqueta @param. La etiqueta @return explica el valor devuelto; no se utiliza en métodos void ni en constructores.

    4.5. Documentar excepciones¶

    /**
 * Divide dos números enteros.
 *
 * @param dividendo número que se divide
 * @param divisor número por el que se divide
 * @return resultado de la división entera
 * @throws ArithmeticException si el divisor es cero
 */
public static int dividir(int dividendo, int divisor) {
    if (divisor == 0) {
        throw new ArithmeticException("No se puede dividir entre cero");
    }
    return dividendo / divisor;
}

    @throws y @exception son equivalentes. Documentan las excepciones que puede producir una operación, sean comprobadas o no comprobadas.

    5. Etiquetas principales de Javadoc¶

    5.1. Etiquetas de bloque¶

    Etiqueta Uso Ejemplo
    @author Autor de una clase o interfaz @author Ana Pérez
    @version Versión del elemento @version 1.2
    @since Versión desde la que existe @since 1.0
    @param Parámetro de método o constructor @param edad edad en años
    @return Valor devuelto @return importe total
    @throws Excepción que puede producirse @throws IllegalArgumentException si edad es negativa
    @exception Sinónimo de @throws @exception IOException si falla la lectura
    @see Referencia relacionada @see java.lang.Math
    @deprecated Explica que el elemento está obsoleto @deprecated Utilizar calcularTotal()

    5.2. Etiquetas en línea¶

    Etiqueta Finalidad Ejemplo
    {@code ...} Muestra código sin interpretarlo como HTML {@code edad >= 18}
    {@literal ...} Muestra texto literal, escapando caracteres especiales {@literal <valor>}
    {@link ...} Enlace a otro elemento de la API {@link java.util.Scanner}
    {@linkplain ...} Enlace con texto normal, sin estilo de código {@linkplain java.util.Scanner Scanner}
    {@inheritDoc} Hereda documentación del método sobrescrito {@inheritDoc}

    Ejemplo de referencias y código en línea:

    /**
 * Lee datos utilizando {@link java.util.Scanner}.
 *
 * La condición {@code edad >= 18} permite comprobar
 * si una persona es mayor de edad.
 * El texto {@literal <alumno>} se muestra literalmente.
 *
 * @see java.util.Scanner
 */
public class EntradaDatos {
}

    5.3. Marcar métodos obsoletos¶

    Cuando un método deja de recomendarse, se puede utilizar tanto la anotación @Deprecated como la etiqueta Javadoc @deprecated.

    /**
 * Calcula el importe utilizando una fórmula antigua.
 *
 * @param precio precio inicial
 * @return importe calculado
 * @deprecated Desde la versión 2.0. Utilizar {@link #calcularTotal(double)}.
 */
@Deprecated(since = "2.0")
public double calcularImporte(double precio) {
    return precio;
}

/**
 * Calcula el importe total.
 *
 * @param precio precio inicial
 * @return importe total
 */
public double calcularTotal(double precio) {
    return precio;
}

    Diferencia importante

    @Deprecated es una anotación Java que informa al compilador y a otras herramientas. @deprecated es una etiqueta de documentación que explica el motivo y la alternativa recomendada. Es habitual utilizar ambas.

    6. Ejemplo completo: clase Alumno documentada¶

    Guardar el siguiente código en un archivo llamado Alumno.java.

    Alumno.java
    /**
 * Representa a un alumno de un ciclo formativo.
 * Permite consultar su información y comprobar si es mayor de edad.
 *
 * @author Departamento de Informática
 * @version 1.0
 * @since 1.0
 */
public class Alumno {

    /** Edad a partir de la cual se considera mayor de edad. */
    public static final int MAYORIA_EDAD = 18;

    /** Nombre completo del alumno. */
    private String nombre;

    /** Edad del alumno en años. */
    private int edad;

    /**
     * Construye un alumno con los datos indicados.
     *
     * @param nombre nombre completo del alumno
     * @param edad edad del alumno; no puede ser negativa
     * @throws IllegalArgumentException si la edad es negativa
     */
    public Alumno(String nombre, int edad) {
        if (edad < 0) {
            throw new IllegalArgumentException("La edad no puede ser negativa");
        }
        this.nombre = nombre;
        this.edad = edad;
    }

    /**
     * Obtiene el nombre del alumno.
     *
     * @return nombre completo del alumno
     */
    public String getNombre() {
        return nombre;
    }

    /**
     * Obtiene la edad del alumno.
     *
     * @return edad expresada en años
     */
    public int getEdad() {
        return edad;
    }

    /**
     * Comprueba si el alumno es mayor de edad.
     *
     * @return {@code true} si tiene al menos 18 años;
     *         {@code false} en caso contrario
     * @see #MAYORIA_EDAD
     */
    public boolean esMayorDeEdad() {
        return edad >= MAYORIA_EDAD;
    }
}

    Programa para probar la clase:

    Main.java
    public class Main {
    public static void main(String[] args) {
        Alumno alumno = new Alumno("Laura García", 19);

        System.out.println("Nombre: " + alumno.getNombre());
        System.out.println("Edad: " + alumno.getEdad());
        System.out.println("Mayor de edad: " + alumno.esMayorDeEdad());
    }
}

    Salida:

    Nombre: Laura García
Edad: 19
Mayor de edad: true

    7. Generar la documentación HTML¶

    7.1. Comprobar que Javadoc está instalado¶

    Desde la terminal de Windows (PowerShell o CMD):

    java -version
javac -version
javadoc --version

    javadoc forma parte del JDK. Si no se reconoce, hay que comprobar que la carpeta bin del JDK está incluida en la variable de entorno PATH.

    7.2. Documentar un archivo Java¶

    Situarse en la carpeta que contiene Alumno.java y ejecutar:

    javadoc -d docs Alumno.java
    • javadoc: ejecuta el generador de documentación.
    • -d docs: indica la carpeta de salida.
    • Alumno.java: archivo que se desea documentar.

    Estructura resultante (simplificada):

    proyecto/
├── Alumno.java
├── Main.java
└── docs/
    ├── index.html
    ├── Alumno.html
    ├── index-all.html
    └── ...

    Abrir docs/index.html con el navegador. Desde PowerShell se puede ejecutar:

    Start-Process .\docs\index.html

    Atención

    La carpeta docs de este ejemplo contiene la salida HTML de Javadoc. No debe confundirse con la carpeta docs de MkDocs, que contiene los archivos Markdown de los apuntes. Si ambos proyectos comparten ubicación, usar una carpeta de salida diferente, por ejemplo javadoc-html.

    7.3. Documentar varios archivos¶

    javadoc -d docs Alumno.java Main.java

    7.4. Generar documentación en español¶

    javadoc -locale es_ES -encoding UTF-8 -docencoding UTF-8 -charset UTF-8 -d docs Alumno.java

    -locale es_ES selecciona el idioma de los textos generados cuando está disponible. Las opciones de codificación permiten trabajar correctamente con tildes y caracteres especiales.

    7.5. Mostrar autores y versiones¶

    javadoc -author -version -d docs Alumno.java

    De esta manera, la información de las etiquetas @author y @version aparece en la documentación HTML.

    7.6. Incluir atributos y métodos privados¶

    javadoc -private -d docs Alumno.java

    Por defecto, la herramienta documenta los elementos public y protected; con -private incluye también los miembros privados y los de acceso de paquete.

    8. Opciones más utilizadas del comando javadoc¶

    Opción Función Ejemplo
    -d Carpeta donde se genera el HTML -d docs
    -public Solo elementos públicos -public
    -protected Elementos públicos y protegidos (predeterminado) -protected
    -package Añade los de acceso de paquete -package
    -private Incluye todos los niveles de acceso -private
    -author Muestra información @author -author
    -version Muestra información @version -version
    -encoding Codificación del código fuente -encoding UTF-8
    -docencoding Codificación de archivos HTML generados -docencoding UTF-8
    -charset Declara el juego de caracteres del HTML -charset UTF-8
    -locale Idioma de la documentación generada -locale es_ES
    -windowtitle Título de la ventana o pestaña -windowtitle "API Alumnos"
    -doctitle Título de la página principal -doctitle "Documentación del proyecto"
    -header Texto de cabecera en las páginas -header "Proyecto DAM"
    -link Enlaza con documentación externa -link https://docs.oracle.com/en/java/javase/21/docs/api/
    -Xdoclint:all Activa todas las comprobaciones de documentación -Xdoclint:all
    -quiet Reduce los mensajes informativos -quiet

    Ejemplo combinado:

    javadoc -d javadoc-html -private -author -version -encoding UTF-8 -docencoding UTF-8 -charset UTF-8 -windowtitle "API de Alumnos" -doctitle "Documentación del proyecto Alumnos" Alumno.java

    Ayuda de la herramienta

    Consultar todas las opciones disponibles en el JDK instalado:

    javadoc --help
javadoc --help-extra

    9. Generar documentación de un proyecto con paquetes¶

    En proyectos reales, las clases suelen organizarse en paquetes.

    mi-proyecto/
└── src/
    └── com/
        └── instituto/
            ├── Alumno.java
            └── Main.java

    Cada archivo comienza con su declaración de paquete:

    package com.instituto;

    Desde la raíz mi-proyecto, generar la documentación del paquete:

    javadoc -d javadoc-html -sourcepath src com.instituto
    • -sourcepath src: indica dónde se encuentra el código fuente.
    • com.instituto: paquete que se documentará.

    Para documentar varios paquetes:

    javadoc -d javadoc-html -sourcepath src com.instituto com.instituto.utilidades

    Para documentar todos los subpaquetes a partir de uno:

    javadoc -d javadoc-html -sourcepath src -subpackages com.instituto

    10. Buenas prácticas al escribir Javadoc¶

    1. Escribir una primera frase breve que resuma la finalidad del elemento.
    2. Explicar qué hace el método, no repetir cada instrucción del código.
    3. Documentar todos los parámetros con @param y los valores devueltos con @return cuando corresponda.
    4. Describir las excepciones relevantes con @throws.
    5. Mantener la documentación actualizada cuando se modifica el código.
    6. Usar {@code ...} para incluir fragmentos cortos de código y {@link ...} para referencias a otras clases o métodos.
    7. Evitar documentaciones ambiguas como «hace un cálculo» o «devuelve un dato».

    Poco útil:

    /** Devuelve la edad. */
public int getEdad() {
    return edad;
}

    Más preciso:

    /**
 * Obtiene la edad actual del alumno.
 *
 * @return edad del alumno expresada en años
 */
public int getEdad() {
    return edad;
}

    11. Actividades¶

    Actividad 1. Documentar métodos¶

    Crear una clase Calculadora con métodos públicos para sumar, restar, multiplicar y dividir dos números. Añadir comentarios Javadoc que incluyan una descripción, @param, @return y, en la división, @throws cuando el divisor sea cero.

    Actividad 2. Documentar una clase¶

    Crear una clase Producto con los atributos nombre, precio y stock, un constructor y métodos para consultar sus valores. Documentar la clase con @author, @version y @since, además de documentar el constructor y todos sus métodos públicos.

    Actividad 3. Generar documentación HTML¶

    Generar la documentación de la clase Producto mediante javadoc. Realizar dos generaciones: una con las opciones predeterminadas y otra con -private -author -version. Comparar los elementos que aparecen en ambas.

    Actividad 4. Personalizar la documentación¶

    Generar la documentación de un proyecto utilizando las opciones -d, -encoding UTF-8, -windowtitle y -doctitle. Abrir el archivo index.html y comprobar los cambios.
